# Changelog

All notable changes to DevHub. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Newest first.

Every session that changes code adds lines under **Unreleased** before it ends. One line per user-visible change, described as behaviour, not as files. Scripts, hooks, skills and docs go under **Infrastructure**.

## [Unreleased]

### Infrastructure
- Dependency policy (ADR 011): `.claude/rules/dependencies.md` (consent and a risk analysis before any package, executable, GitHub Action, host or version change; a vendored copy first), the inventory `docs/DEPENDENCIES.md`, and `Scripts/check-dependencies.sh` with `Scripts/allowed-tools.txt` and `Scripts/allowed-hosts.txt` in `build.sh` and CI. `actions/checkout` is pinned to its commit SHA.
- `docs/customization.md`: the map from a need to the `.devhub/` mechanism that covers it, a worked example of a chat command tab built from scripts, actions and a custom tab, and the schema gaps that such a tab still has. Linked from the README, `AGENTS.md`, the example folder and the `extensions` skill.

### Added
- Utils holds the extra tabs: the tools, every custom tab of the `.devhub` folders, and any built-in tab you move there. A row of sub-tab buttons at the top chooses one. Right-click a tab in the tab bar for "Move to Utils", or a sub-tab in Utils for "Show in Tab Bar"; the moved tab stays on screen in its new place, and the choice is saved for every project. Home and Utils stay in the bar. A notification, a palette entry or a row action that opens a moved tab opens Utils on it. `DEVHUB_TAB` takes `utility.compressVideo` and a tab placed in Utils.
- Custom tabs: a tab starts as a sub-tab of Utils. `"placement": "bar"` in the tab file puts it in the tab bar after the built-in tabs; a right-click wins over the file.
- Custom tabs: `inputs` on a tab are shared by every row. They show in a bar under the toolbar, their values are saved per project and tab, and every action and source script of the tab gets them as `DEVHUB_INPUT_<KEY>` and `{key}`. A text or number input with `recent: true` keeps its last 12 values in a clock menu next to the field, with Forget. The example folder has a `chat` tab that uses them.
- Actions: `run: {"copy": "…", "open": "…"}` puts the rendered text on the clipboard and opens a link or file, without a script. The prompt shows the text live under the inputs and the button says Copy. A custom tab ends with a Recent section: the last 30 copied texts of the project for that tab, with Resend, Remove and Clear.
- Actions: an option of a `choice` input can carry `confirm`. When that option is chosen, its text is the confirmation and wins over the action's own `confirm`; an action without inputs asks too when a shared tab input has one. So a PROD environment asks and QA does not.
- Settings → AI usage → Show usage for: "Off". With Off, DevHub reads no token and calls neither api.anthropic.com nor api.github.com; the usage strip and the menu bar percent stay empty.
- Every tool DevHub starts gets the telemetry and update-check opt-out variables of its maker: `DO_NOT_TRACK`, `HOMEBREW_NO_ANALYTICS`, `GH_TELEMETRY=false`, `GH_NO_UPDATE_NOTIFIER`, `CIRCLE_NO_TELEMETRY`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`.
- Operations tray: every running or failed action shows as a card at the bottom of the tab, over the list and above the Output panel, with its steps, the last output line, the progress of a script, Stop, Retry, Copy Error and Full Output. Several actions at once are several cards. The tray floats, so the list no longer jumps when a card appears or grows. A pull request window has its own tray.
- Simulators → Remove Apps from All…: runs as an operation with "3/10 · iPhone 16", a bar and Stop in its card, instead of a progress line that grew the toolbar.
- Simulators and Git: a checkout badge. Gray "Main checkout · <branch>" for the main checkout; orange "Worktree · <name>" or "Branch · <name>" when the build or the Git actions use another checkout. A click opens the menu as before.
- Simulators: paired iPhones and iPads show in a "Devices" section at the top of the list, with their iOS version, a `device` tag and "Connected" or "Not connected". A connected device can be the target: Build & Run builds for it with the signing of the project, installs the app with `devicectl` and launches it with the launch profile and the device ID. Clean install removes the app first. Profile defaults are written into the app's preferences on the device. The identity panel reads the installed version, the stored profile and, for a build made by DevHub, the identity hook. Uninstall and favorites work for a device. Logs, the mock server, Run & Attach, deep links, push, erase, app data and QA settings are not available on a device and are hidden in its row; the run bar disables Run & Attach for a device target. The toolbar counts simulators and devices apart. Scripts get `DEVHUB_SIMULATOR_KIND` (`simulator` or `device`).
- Simulators: without a saved target, a booted simulator is the target before a connected device.
- Simulators: the run bar shows a tag with the version of the Xcode that builds the project (`Xcode 26.1`). Its hint names the app path and where the choice comes from: Settings → Projects, `xcode.developerDir`, or `xcode-select`. The Xcode of `xcode-select` and the chosen one are listed with their version even when Spotlight does not find them.
- Simulators: the status script can put tags on a simulator with a `tags` list in its `state` line (`text`, optional `tint`, `icon`, `hint`). They show after the identity line of the row and under the target of the run bar. Tags of a script `view` row take `icon` and `hint` too.
- Launch profiles: `launch.profiles[].tint` sets the colour of the profile tag in the identity summary and panel. It wins over the red of a production profile.
- Xcode 27 support for the simulator window: Xcode 27 has no Simulator.app, so Build & Run, Launch, Apply & Relaunch and the row menu failed with "Unable to find application named 'Simulator'". DevHub now opens the app of the project's Xcode: Simulator.app up to Xcode 26, Device Hub from Xcode 27 (it boots the simulator, then shows it with `devices://device/open?id=<udid>`). The row menu says "Open in Simulator" or "Open in Device Hub". The example `list-devices` script opens either app.
- Worktrees → New…: a line under the branch field shows the folder of the new worktree. "Keep Inside the Project" adds `.worktrees/` to `.git/info/exclude`; from then on new worktrees go to `<project>/.worktrees/<branch>`, and `git status` of the main checkout does not list them. A project whose `.gitignore` already ignores `.worktrees/` works the same way without the button. `git.worktrees.folder` in the config still wins. Worktrees you already have stay where they are. This applies to every place that creates a worktree: New…, the Git tab, the Pull Requests tab, the command palette and a build from a branch.
- Drop videos on the DevHub icon in the menu bar: the icon lights up while a video is over it, and the drop opens Utils → Compress Video and starts the compression. This works while the panel is closed, so a screen recording can go straight from Finder or the Desktop.
- Utils tab (⌘9) → Compress Video: drop screen recordings or other videos on the tab, or choose them. DevHub compresses each one with ffmpeg (x264) at High, Balanced or Small quality, with or without sound, and saves "<name> compressed.mp4" next to the original. Each row shows the source facts, progress with the time left, then the new size and the saving; Stop leaves no file; a done row opens, shows in Finder or drags the file into a chat. When ffmpeg is missing, the card says so and "Install ffmpeg" runs `brew install ffmpeg` with the current step; videos added before wait and start after the install. A notification arrives when a video is done while the panel is closed.
- Settings → Doctor: a row for `ffmpeg` (ffmpeg and ffprobe with libx264, used to compress videos), with `brew install ffmpeg` to copy.
- Simulators → QA settings → Frame → "Add the device frame": screenshots, GIFs and converted MP4 videos get the device frame of Xcode around them, with the side buttons and round screen corners, for iPhone and iPad simulators. DevHub reads the frame from the Xcode on this Mac. The choice is saved. A device without a frame keeps the plain screenshot, and Recent says why; a GIF or video of such a device fails with the reason. A framed GIF or video has "framed" in its file name.
- Simulators → QA settings → Video → "Convert": a GIF (320, 480 or 640 px wide) or a smaller MP4 (720p H.264 or 1080p HEVC) from the last recording or from any `.mov`, `.mp4` or `.m4v` file. The file goes next to the source and never replaces another file. The work is an operation with progress and a stop button. A GIF keeps one frame for each change of the screen, so a still screen becomes one long frame. A failed or stopped GIF leaves no file.
- Simulators → QA settings: "Record" and "Stop" record the screen of a booted simulator into a `.mov` file on the Desktop. The round corners of the screen are recorded black. The line shows the time of the recording, the recording is an operation with a stop button in the panel and in the footer, and the file name links to Finder. Quitting DevHub stops every recording, so the files are written.
- Simulator scripts: the App Data panel shows config actions with the new `simulators.appData` placement as buttons under its header. They run for the simulator of the row and the app of the panel, and the panel reads the data again when the action ends. Two new context variables for every script: `DEVHUB_GROUP_CONTAINERS` (the app group containers of the app, one "group ID, tab, folder" line each; empty on a simulator that is not booted) and `DEVHUB_SIMULATOR_STATE` (`booted`, `shutdown`, `booting` or `shutting-down`). `appData` is a new `refresh` target. The example "Clear App Caches" action also clears the caches of the app groups and shows in the App Data panel.
- Settings → Disk: the sizes of the Xcode, simulator and package manager folders, each with "Delete…" and an inline confirmation: DerivedData of deleted projects, unavailable simulators, Archives, device support files, the Swift Package Manager and CocoaPods caches, and folded lists of DerivedData by project and of simulator runtimes. The header shows the total and "Scan Again". Each delete is an operation card with the command (`rm -rf`, `xcrun simctl delete unavailable`, `xcrun simctl runtime delete`). DevHub deletes only inside DerivedData, `~/Library/Developer/Xcode` and `~/Library/Caches`; nothing goes to the Trash.
- Write with AI and Explain: "Write with AI" in the commit box writes the commit message from the staged diff and the recent commit subjects. "Write with AI" in the new request form writes the title and the description from the diff of the branch, the commits and the template. "Explain" in the details of a request shows what it changes, the risky places, what changed since your review and what to check. DevHub runs Claude Code (`claude -p`) or Copilot CLI (`copilot -p`) once and puts the answer into the field; nothing is committed or created on its own. Settings → AI usage → "Write with AI and Explain use" chooses the tool, the arrow next to each button picks the other one for one run, and `ai.textCommands` in `project.json` changes the commands. Each run is an operation card with Stop; a failure shows the reason from the tool.
- Pull Requests: "Reviewers" and "Assignees" menus under the review block of the details. They list the people of the project (GitHub assignable users, GitLab active members) with a check mark on the current ones; a click requests a review, removes a reviewer, assigns or unassigns that person (`gh pr edit`, `glab mr update`). They show on an open request that you wrote or can merge. Each change is an operation card and the list reads again after it.
- Pull Requests: "Changed since your review". When you approve, comment, ask for changes or mark every file as viewed, DevHub saves a fingerprint of the diff of each file. After new commits, a line above the files says "3 files changed since your review 2 days ago", the files get an orange "changed since review" tag, and "Show Only These" lists only them. "Viewed" marks now survive a restart and drop off a file whose diff changed. "Forget" removes the saved review of a request. Settings → Pull Requests → "Remember what I reviewed" (on by default) turns it off and removes everything DevHub saved. No extra request goes to GitHub or GitLab.
- Simulators: "App Data…" in the row menu of a booted simulator shows the data of the app under the row: the data container, the size of Documents, Application Support, Caches, Preferences, tmp and the app group containers, the database files, and the user defaults of the app and of each app group. Edit, switch, add and delete keys of type string, number and boolean; filter the keys. "Reset App Data…" (inline confirmation) stops the app and deletes its files and defaults, the app group data too when you choose it. Each change shows as an operation card under the panel header.
- Crash reports: after DevHub launches the app on a simulator, a crash of that app shows a red block in the run bar: the exception, the first frame of the app code with its file and line, the messages of the report, the stack on demand, Open Report and Fix with AI (Claude Code or Copilot CLI). It is also a Recent line and a notification of the new kind "App crashes on a simulator". DevHub starts no process for this: one file system event source on `~/Library/Logs/DiagnosticReports` wakes it when a report is added.
- Xcode per project: Settings → Projects has an Xcode picker for each project ("Default" or one of the installed Xcode apps, newest first), and `xcode.developerDir` in `.devhub/project.json` sets it for the team. DevHub runs `xcodebuild`, `xcrun` (simctl) and `xed` with that `DEVELOPER_DIR` and opens that Xcode. The selected project shows which Xcode its builds use.
- Operations in Worktrees and Pull Requests: Fetch, Prune, Clean Finished and New show a card under the Worktrees toolbar; Delete and Bootstrap show it under the row, and a failed bootstrap has Retry. Request actions (approve, ready or draft, update, merge, auto-merge, retry or cancel the checks, comment, request changes, line comments, threads, retry a job, CircleCI re-run, cancel and approve) show it under the request row, at the top of the details pane and in a request window; a failed request action has Retry.
- Operations: an action you start shows a card at its place while it runs and after it ends: under the Git header (fetch, pull, push, rebase, stash, switch…), under the commit box, under a tile grid, a script row, the Git pills or a toolbar for config actions and scripts, under the Simulators toolbar and in the push panel. The card lists the commands of the action as steps with a spinner, a check mark or a cross and their time, the last output line, and the progress bar of a script with Stop. A failed action keeps a red card: the message, the failed step with its exit code, the lines of its output that explain the failure (`error`, `fatal`, `rejected`, `hint` and similar), Retry, Copy Error and Full Output. A commit whose push failed shows an orange card. A success shows a green line for 4 seconds.
- The footer shows the running operation with its progress, "N running", or "N failed" in red. A click lists the operations of this session (the last 30 finished ones) with the same cards.
- Pull Requests with CircleCI: "Auto re-run" on the line of the checks title runs the failed jobs of a workflow again each time it fails, up to 3, 5, 10 or 20 times. DevHub checks every minute while it runs, also with the panel closed, and the plan survives a restart. Each re-run, the pass, the stop after a cancel and the stop after the last try are lines in Recent and notifications. A workflow that ran again waits up to 10 minutes for its new workflow.
- Pull Requests with CircleCI: "Previous CircleCI runs" under the jobs lists the earlier workflows of the request with their state, time, failed jobs and failed tests, folded by default. DevHub saves every finished workflow it reads (20 per request). "Forget" removes them.
- Settings → Doctor checks the `circleci` tool. A version below 1 shows in orange as "<version>, needs 1 or newer" with `brew upgrade circleci` as the command to copy.
- Pull Requests with CircleCI: when the project runs on CircleCI (`.circleci/config.yml` in the main checkout, or `ci.kind: "circleci"` in `project.json`) and the `circleci` tool (1.0 or newer) is installed and logged in, the details show the jobs of each CircleCI workflow of the last commit instead of the external status links: the state of every job, the log of a finished job, "Re-run Failed" and "Re-run All" on a finished workflow, "Cancel" on a running one (inline confirmation), and an Approve button on a job that waits for approval (inline confirmation). A failed job lists its failed tests with their messages. A test that CircleCI Insights knows as flaky gets a "flaky · flaked N times" tag, and the job row shows "flaky" or "N of M flaky". Without the tool or the login, a line above the jobs names the command and runs it in Terminal. Every `circleci` command lands in the Output panel.
- Notifications: an Inbox pane next to the events. It lists the unread GitHub notification threads or the pending GitLab to-dos of this repository: who mentioned you, asked for your review or approval, assigned you or commented, with the request or issue. Open the request in DevHub, open it in the browser, mark one or every item as done on the host. A new item posts a notification of the new kind "Inbox" (its own switch in Settings) and the bell badge counts the Inbox items.
- Pull Requests: a changed file in the details can show the whole file at the last commit with the changes in place (the text-lines button in the file header; DevHub reads the file from GitHub or GitLab once per request). The compass button opens the whole file in the browser at the last commit, and "Open in Browser at This Line" in the menu of a diff line opens it at that line.
- Pull Requests: "Watch" in the row menu of a request by someone else. DevHub reads the list every minute while a request is watched and reports an approval, a request for changes, failed checks, a new comment and the merge or close of it, in Recent and as a notification of the new kind "Watched pull requests" (its own switch in Settings). The row shows a "watching" tag. "Stop Watching" ends it; a merge or close ends it too.
- Output panel: "Open in Editor" and "Save Output…" in the menu of an entry, and a Save button in the header for every shown command. "Open in Editor" writes the transcript to `~/.devhub/scratch/` and opens it in the editor from Settings.
- "Fix with AI" on a failed test run (Worktrees) and on the build errors of the run bar: DevHub writes the failed tests, their messages and the compiler errors into a prompt file and starts Claude Code or Copilot CLI in the terminal inside the checkout. "Fix Threads with AI" on a pull request offers the same two tools. The command of each tool comes from `ai.commands` (`ai.reviewCommand` still works as the Claude command).
- Pull Requests: a new comment on your own request names its author ("sam commented on #12", "sam and lee commented on #12 (3 new comments)"). Your own comments no longer count as news. DevHub reads the last 10 comments and the last review comments of a request (GitHub) or the last 20 notes (GitLab) with the list.
- Pull Requests: while the panel is closed, DevHub reads the open requests every 2 minutes instead of 5, so the reports of your own requests arrive sooner.
- Notifications screen: the bell in the header (with a badge of unseen events) lists every event of the last 30 days by day: builds, test runs, changes of your requests, scripts and the other actions of the app. A filter by kind, the header search, Clear, and an arrow on a row opens the place of the event (a request, the review list, the Worktrees tab, the run bar). Home → Recent shows the last 8 and "Show All".
- A click on a macOS notification opens DevHub at the place of the event. A notification without a place opens the Notifications screen.
- Settings → Notifications: one switch per kind (builds, test runs, requests waiting for your review, reviews, checks, comments, merged or closed requests, scripts), each with a description of what it sends and what a click opens.
- Pull Requests: DevHub reports changes of your own open requests. An approval ("#12 approved by alex"), a request for changes ("Changes requested on #12 by sam"), failed checks or pipeline, new comments, a merge or a close show in the Recent list on Home and, while the panel is closed, as a macOS notification. Settings → Notifications → "Notify about my pull requests" turns the notification off. The changes come from the read of the open requests every 5 minutes.
- AI: "New" in the toolbar starts a new Claude Code or Copilot CLI session in the project folder, in the terminal from Settings. A worktree row has "Start AI Session Here" with both tools, and the ⌘K palette lists "Start Claude Code in <project>" and "Start Copilot CLI in <project>".
- Build & Run: a "Build" button (⌘B) compiles without an install or a launch. The result line says "Built <scheme>, not launched" and the app path is in the build log. A `kind: command` project runs `build.command` only. `builtin.build` in `home.quickActions` adds the tile to Home, and the ⌘K palette lists "Build".
- Output panel: drag its top edge to change the height (a double-click restores it; the height is saved). "Follow" keeps the list at the newest command, or lets you stay where you scrolled. The filter menu has "Show reads" and "Failed only". Every entry shows its start time, and a right-click copies the command or the output, or opens its folder in the terminal or Finder.
- Worktrees: a checkmark button in a row (and "Run Tests" in its menu) runs the tests of that worktree with the scheme and target simulator of the run bar. A panel under the row shows the step, live counts, then the result: passed, failed and skipped counts, the time, every failed test with its message and file (a click opens the file at that line), compiler errors when the build broke, "Run Again" and "Open Results in Xcode" for the `.xcresult` bundle. Stop with the stop button. A notification arrives when the panel is closed.
- Pull request details have a review block: who approved, who asked for changes, who is still expected to review (a requested reviewer without an answer) and the assignees. GitHub reads the latest review of each person and the review requests; GitLab reads the review state of each reviewer.
- Pull request comments are readable in full: no three-line cut, inline markdown (code, bold), selectable text and the time of each comment and reply. A thread opened under its diff line shows its replies at once.
- Pull request details hide noisy files (tests, Xcode project files, lock files by default) from the file list. "Show N hidden" in the files header brings them back, "Hide N" hides them again. `git.pullRequests.hiddenFiles` sets the patterns; an empty list hides nothing.
- Pull request checks are grouped by stage (GitLab) or by workflow (GitHub), with the state of each group. Every job shows how long it ran, an "allowed to fail" mark, and the failure message (GitLab) or the check title (GitHub) when it failed.
- The side-by-side layout of the Pull Requests tab shows the author, the dates, the branches, the counts and the tags of the selected request in the details header.
- Settings → AI usage → "Show usage for": Claude and Copilot, Claude only, or Copilot only. The usage strip and the menu bar percent follow the choice, and DevHub reads only the chosen providers.
- Pull Requests: the filter menu narrows the list by several labels at once, by author, by assignee and by requested reviewer, next to the target branch, conflicts and ready-to-merge filters. A click on a label tag in a row adds or removes that label in the filter. Every active filter is a chip with its own ✕.
- Home → Scripts: drag a script row onto another row to change the order, or use Move Up and Move Down in the row menu. The star button adds a script to the favorites; favorites stay at the top. The order and the favorites are saved per project.
- Build & Run: the button next to the scheme picker adds a scheme or target to the picker. It suggests the schemes and targets of the project that the picker does not show (from `xcodebuild -list`), and takes any typed name. A scheme added this way can be removed again. The list is saved per project.
- Build & Run: the run bar lists the compiler errors and warnings of the build, errors first. A click opens the file at that line in the editor from Settings.
- Simulators: the sliders button in a row opens QA settings for a booted simulator: light or dark appearance, text size, a clean 9:41 status bar, a location from a city list, the language and region, privacy permissions for the app (grant, revoke, reset) and a screenshot to the Desktop.
- Home has a "Today" card: requests that wait for your review, your requests with failed checks, finished worktrees and booted simulators. A click opens the right tab (or the request).
- Switch projects from the keyboard: ⌃⌘1 to ⌃⌘9 select the first nine projects in the order of Settings → Projects, and the project menu shows these shortcuts. The ⌘K palette lists "Switch to project …" for the other projects.
- Settings → Project config → "Create .devhub Starter" writes `.devhub/project.json` with the values DevHub found for the project (name, scheme, bundle ID, remote, code host, base branch) and opens it in the editor. A good first step for a new project; the example folder stays for a full reference.
- Pull request details list every check or pipeline job of the last commit, failed first. The log button shows the last 200 lines of a job log inside DevHub, with Copy Log. Retry runs one failed or cancelled job again. Works for GitHub Actions and GitLab jobs.
- Pull request diffs: hover a line and click the bubble with a plus (or right-click it, "Comment on This Line…") to start a new review thread on that line, on GitHub and GitLab. The box opens under the line; ⌘Return posts, Esc closes.
- Pull request details have a comment box. "Comment" (⌘Return) posts a comment on the request on GitHub and GitLab. "Request Changes" sends the text as a review that asks for changes, on GitHub, for a request by someone else. A failed post keeps the text.
- A right click on the menu bar icon opens a menu: Show DevHub, the list of projects (a click switches to the project and shows DevHub), Keep Mac Awake, Settings… and Quit DevHub. A left click still opens or closes DevHub.
- Settings → General → Window: "Normal window" turns DevHub into a window app. It gets a title bar, a Dock icon and a main menu (DevHub, File, Edit, Window). The close button and ⌘W hide the window and DevHub keeps running. The menu bar icon, the global shortcut and a click on the Dock icon show the window on the current desktop; the icon and the shortcut hide it when it is already in front. The window opens at launch when it was open at quit. "Menu bar panel" stays the default.
- Git: pin, label and add a note to a local branch. The star (or "Pin to Top" in the menu) moves the branch into a "Pinned" group at the top of Local, and "Delete all…" never offers it. "Add Labels & Note…" opens a form under the row; labels show as coloured tags, the note under the subject, and the search finds both. The marks stay in DevHub, per project.
- Simulators: drag a favorite row onto another favorite row to change the order of the Favorites section. The order is saved, and a new favorite goes to the end.
- AI tab: a star on a session row adds it to the favorites. Favorites come first in their own section, stay visible in the "This project" scope, and come first in the ⌘K palette.
- Home has a "Keep Mac awake" switch. While it is on, the Mac does not go to sleep when idle, and the menu bar icon shows a cup. The ⌘K palette turns it on and off. Quitting DevHub turns it off.
- The `network.toolbar` placement puts config actions under the filters of the Network tab, with the chosen simulator. `refresh: ["network"]` reads the mock sets again after an action.
- Scripts, commands and the status script get `DEVHUB_PROFILE` (the launch profile of the simulator), `DEVHUB_HOST` (`github` or `gitlab`), `DEVHUB_APP_CONTAINER` and `DEVHUB_DATA_CONTAINER` (the app and data folders of the app on the simulator). The example `.devhub` folder has a "Clear App Caches" action that uses them.
- The run bar profile picker marks a `production: true` profile with a warning sign, and shows a red "production" tag next to the picker while that profile is selected.
- DevHub has an app icon: a `</>` sign on an indigo square. It shows in Finder, in the Dock when the Dock icon is on, and in notifications.
- Settings → Projects: the circle arrows button finds the scheme and bundle ID of a project again in the project files. Settings → Global config folder shows `~/.devhub` with Reveal, or "not created".
- Settings → Doctor lists git, xcodebuild, simctl, gh, glab, copilot, claude and python3 with the version and path, or "missing" with the install command. It also shows the Accessibility and Notifications permissions. "Check Again" reads them again.
- macOS notifications while the panel is closed: a finished or failed Build & Run, more requests waiting for your review, and every `notify` line of a script. Settings → Notifications has the switch and asks for the permission once. The menu bar icon shows a circle while a build runs and a red dot after a failed build until the panel opens.
- Command palette (⌘K or the ⌘ button in the header): one search over tabs, built-in and config actions, simulators (Build & Run on, make target), local branches (switch, Build & Run, create worktree), worktrees (open, Build & Run), pull requests and AI sessions (resume). Arrow keys move, Enter runs, Esc closes. An action with inputs asks for them inside the palette.
- GraphQL in the Network tab: a request shows its operation name and a `query`, `mutation` or `batch` tag, the details list the operations, variables and errors, and a response with `errors` counts as failed. A mock rule can match a GraphQL operation name (`*` allowed), and "Mock This" on a GraphQL request fills it in. The mock set file format is documented in `docs/extensions.md` section 9.
- Custom tabs from `.devhub/tabs/*.json` appear after the built-in tabs (⌘9 for the first one). A section lists its actions with Run, inputs and results, or the rows that its source script prints, read again on open, by hand or every N seconds. Actions placed at `tab.<id>` get their own section. The header search filters the rows.
- Launch identities from `launch.identity` in `.devhub/project.json`: the identity panel of a simulator and the run bar choose an ID (New, Saved, Own) and an alias. - Home: project card with Finder, editor, Terminal and Repository buttons, quick actions grid (order and hiding from `home.quickActions`), Scripts list with last run time and "Run chmod +x" hint, config problems list. The temporary "Run a test command" section is gone.
- Repository and New pull request (or merge request) buttons open the GitHub or GitLab web page of the current branch.
- `DEVHUB_PROJECT`, `DEVHUB_RUN_ACTION`, `DEVHUB_REQUEST_ACTION`, `DEVHUB_SEARCH`, `DEVHUB_SHOW_OUTPUT` and `DEVHUB_SNAPSHOT_DELAY` and `DEVHUB_CREATE_EXAMPLE` help to check the UI without a screen.

- Git tab is real: checkout picker, branch and hash, tags (clean, upstream, ahead and behind base, stash count, last fetch), and a banner for a rebase, merge or cherry-pick in progress with Continue, Abort and Terminal.
- Git pills: Fetch, Pull (fast-forward only), Push (sets the upstream when there is none), Force Push, Rebase on base, Update base without switching, Stash, Pop Stash, config actions with placement `git.pills`, and Terminal, New PR/MR and Web icons. Force Push and Rebase ask for an inline confirm.
- Git segments Local, Remote, History and Changes. The chosen segment is remembered.
- Changes segment: diff view (4 000 line cap, notice for binary files), stage, unstage, discard (inline confirm), open in editor, Stage All, Unstage All, commit box with a prefix from `git.commitPrefix`, Amend, Commit (⌘↩) and Commit & Push.
- Pull request or merge request line through `gh` and `glab`. When the tool is missing or not logged in, the line shows the command with a copy button.
- Worktrees tab is real: toolbar (base, DerivedData total, Fetch with prune, Prune, Clean Finished, New worktree), sections (main, in progress, finished, missing), rows with tags and DerivedData size, delete with inline confirm and checkboxes, create from a local branch, a remote branch or a new branch, copy of the `git.worktrees.include` files, bootstrap script, and config actions with placement `worktrees.row`.
- `branch` and `worktree` action inputs are searchable pickers over live data. `branch` with `default: "current"` starts with the branch of the checkout chosen in the Git tab. `cwd: checkout`, `DEVHUB_CHECKOUT_PATH` and `DEVHUB_BRANCH` follow that checkout.
- Logs tab is real: one chip per simulator stream, a "+" button with a searchable list of booted simulators, several streams at once, level filter, search, Pause with a count of waiting lines, Copy visible lines, Clear, and up to 5 000 lines per stream with a counter for dropped lines. Streams and levels are saved.
- Log lines are masked before they are stored: bearer tokens, JWTs and secret keys never reach the list.
- Simulators tab shows the live list of available simulators.
- Simulators run bar: pick a scheme, configuration, build source (main checkout, a worktree or a branch with an existing worktree), Fast and Clean install, then Build & Run, Run & Attach or Launch. Shows build progress, the result and a Run & Attach accessibility notice. Row actions launch, send a deep link or a push, stream logs, remove apps, boot or shut down, and uninstall. Favorites star, target marker, Open in Simulator.app and Copy UDID.
- AI tab is real: Copilot sessions from `~/.copilot/session-state` and Claude sessions from `~/.claude/projects`, grouped by day, with a provider switch (Copilot, Claude, Both), a scope (This project, All), search, count, refresh and Resume in the configured terminal.
- Usage strip is real: Claude session and week limits and Copilot premium requests, with reset times, plan, Retry, and a refresh every 5 minutes while the panel is open.
- Settings can show the usage strip and the Claude or Copilot usage percent in the menu bar.
- Debug switches `DEVHUB_GIT_SEGMENT`, `DEVHUB_GIT_OPS`, `DEVHUB_LOG_STREAM`, `DEVHUB_LOG_REDACT_CHECK`, `DEVHUB_AI_SCOPE`, `DEVHUB_AI_PROVIDER` and `DEVHUB_USAGE_EXPAND`.

### Changed
- The Home empty state and the example `project.json` (now with `xcode.schemes` and `xcode.bundleIDs`) were polished.
- `DEVHUB_PROJECT_PATH` and the working folder no longer choose the project. Use the project list or `DEVHUB_PROJECT`.
- A failed secret command (for example `gh auth token` without a login) no longer opens the Output panel. `gh auth token` counts as a secret command.

### Fixed
- The change count says "1 change" instead of "1 changes".
- A cancelled stream shows as "Cancelled", not as a failure.
- `BuildStore`, the store behind the Simulators run bar, was missing from the feature commit (never added to git) and the app did not build. Reconstructed from its call sites on a temporary branch: builds with `xcodebuild`, locates, caches, installs and launches the app, and runs Run & Attach. Known gap: a branch build source needs an existing worktree for that branch; it does not create one.

### Removed
- The sample data banners on Git, Worktrees, Logs, AI and Simulators, because these screens now show live data.
